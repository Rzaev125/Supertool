# Windows installer

ShiftWheel 0.7.0 поставляется как переносимый ZIP и как автономный установщик
`ShiftWheel-0.7.0-win-x64-setup.exe`. В установщике находятся приложение и все
переносимые модули из того же выпуска: загрузка компонентов при установке не нужна.
Требуются Windows 10/11 и совместимая с x64 система.

Установщик размещает приложение в `%LOCALAPPDATA%\Programs\ShiftWheel` для
текущего пользователя. Права администратора не запрашиваются. В меню «Пуск»
появляется ShiftWheel; ярлык рабочего стола можно выбрать отдельно. Установщик
не включает автозапуск, ассоциации файлов, службы, драйверы или установку общих
системных библиотек. По завершении приложение не запускается автоматически.

Если ShiftWheel работает, установка и удаление просят сначала закрыть его.
Дождитесь завершения конвертации либо отмените её сами, затем выберите «Выход»
в меню значка ShiftWheel в области уведомлений. Установщик не завершает процессы
и не останавливает конвертацию. Закрытие окна задач не заменяет выход из приложения.

При обновлении запускайте новый установщик. Файл `ShiftWheel.ini` рядом с
приложением сохраняется: он не включён в дистрибутив и не принадлежит установщику.
Переносимая копия хранит собственный INI; установщик не переносит его автоматически.
При необходимости скопируйте этот INI в установленную папку при закрытом приложении.

Удалить установленную копию можно через список приложений Windows или
`unins000.exe` в папке приложения. Удаляются файлы, установленные пакетом.
Настройки и добавленные пользователем файлы, включая файлы во вложенных папках,
остаются. Установщик не удаляет папку приложения рекурсивно. Файлы самого пакета,
например модули и README, считаются управляемыми файлами и заменяются при обновлении.
Папки с перенаправлениями/junction/symlink не допускаются для установки и удаления.

Текущий выпуск **не подписан цифровой подписью издателя**. Windows может показать
предупреждение о неизвестном издателе. Файл `.sha256` позволяет сверить байты
дистрибутива; контрольная сумма не заменяет цифровую подпись.

## Сборка

Сначала соберите и проверьте приложение, затем подготовьте переносимый пакет:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-installer.ps1
```

Скрипт проверяет версию `release.json`, SHA-256 исполняемого файла и ProductVersion
в его PE-ресурсе. Это не позволяет назвать старый исполняемый файл выпуском 0.7.0.
Он создаёт отдельную папку staging, включает известные файлы выпуска, `docs` и
`modules`, исключает личный INI и временные/рабочие файлы. В JSON-манифесте
фиксируются относительные пути, размеры и SHA-256 каждого файла.

Результат и его `.sha256` / `.payload.json` находятся в `out`. При повторной сборке
ранее созданный Setup.exe той же версии сохраняется в `out\installer-history`.
Старые ZIP-выпуски не меняются. Исходники staging, лог компилятора и промежуточный
установщик остаются в отдельной `build\installer-build-*` для проверки результата.

Стабильный AppId: `{00BEDB6F-6D79-4F1C-AAB6-B13F51553090}`. Менять его между
обновлениями не следует: Windows использует его для одной записи удаления продукта.
Обычная сборка создаёт запись удаления для текущего пользователя. Заданный через
`/DIR` путь должен совпадать с выделенной папкой приложения.

## Инструменты и происхождение

Используется [Inno Setup 6.7.3](https://github.com/jrsoftware/issrc/releases/tag/is-6_7_3).
Скрипт `scripts/fetch-installer-tools.ps1` загружает официальный архив по закреплённой
ссылке, проверяет SHA-256 из `scripts/installer-tools.json` и распаковывает его как
данные. Исходный установщик компилятора не запускается. На этой машине дополнительно
проверена действующая Authenticode-подпись архива: `Pyrsys B.V.`. SHA-256 совпал с
digest официального GitHub release asset.

Для распаковки используется `innounp` из [репозитория его автора](https://github.com/jrathlev/InnoUnpacker-Windows-GUI)
на конкретном commit `032d64c782efc6b36766d8f9c3b1b2f042144a58`; его архив также
закреплён SHA-256. Кэш и распакованные инструменты остаются только в `tools` этой
рабочей папки. Лицензии сохранены в `installer/tool-licenses` и копируются вместе
с инструментами. Эти вспомогательные инструменты не входят в установленное приложение.
Авторские уведомления самого Inno Setup сохранены в генерируемом установщике.

Политики основаны на официальной документации Inno Setup:
[PrivilegesRequired](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm),
[AppMutex](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm),
[CloseApplications](https://jrsoftware.org/ishelp/topic_setup_closeapplications.htm),
[CreateUninstallRegKey](https://jrsoftware.org/ishelp/topic_setup_createuninstallregkey.htm).

## Проверки в изолированной папке

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/installer_payload_tests.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/installer_lifecycle_tests.ps1
```

Первая проверка проверяет реальные файлы staging и запрет неподтверждённой версии.
Вторая собирает маленькие тестовые пакеты 0.4.0 и 0.7.0, устанавливает, обновляет и
удаляет их. Проверяются блокировка при занятом mutex приложения, отказ от чужого
пути установки, обязательный явный тестовый режим, хеши установленных файлов,
замена программы при обновлении, сохранение INI и посторонних файлов при обновлении
и удалении. Также проверяется отсутствие изменений записи удаления и ярлыков
реального пользователя. Сам фиктивный исполняемый файл теста не запускается.

Для полного пакета соберите отдельную тестовую версию:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-installer.ps1 -TestRoot build/installer-tests/full-050
# Подставьте выведенный путь к файлу *-ISOLATED-TEST.exe:
powershell -NoProfile -ExecutionPolicy Bypass -File tests/installer_lifecycle_tests.ps1 -SetupExe "<полный путь>" -TestRoot build/installer-tests/full-050 -LaunchInstalledApp -ConvertInstalledMedia
```

Тестовая сборка на этапе компиляции привязана к конкретной папке внутри
`build\installer-tests`, отключает запись удаления и ярлыки и требует параметр
`/SHIFTWHEELTEST=1`. Обычный установщик не содержит переключателя, позволяющего
отключить эти ограничения или переехать в тестовый путь. Тестовая сборка помечена
`ISOLATED-TEST` и не предназначена для распространения.

Эти проверки не устанавливают продукт в настоящий `%LOCALAPPDATA%\Programs`.
Опции `-LaunchInstalledApp` и `-ConvertInstalledMedia` проверяют запуск именно
установленной копии, её штатное завершение и реальные конвертации видео через
поставляемые модули с проверкой прогресса и сохранности исходников. Для проверки
конвертаций используется Python из среды разработчика; самому продукту он не нужен.
Обычная интеграция с меню «Пуск» и списком приложений проверяется по скрипту,
а не путём изменения рабочего профиля пользователя.
