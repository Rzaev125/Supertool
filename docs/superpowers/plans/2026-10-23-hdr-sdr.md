> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline.

**Goal:** Add bounded HDR→SDR photograph conversion and strengthen post-resize content verification.

**Architecture:** Existing pinned AVIF/HEIC decoders normalize container geometry to16-bit PNG, then native row-streamed WIC tone mapping produces8-bit sRGB before existing resize/encoding. SDR paths stay unchanged.

**Tech Stack:** C++20 / Win32 / WIC / existing codec modules, Python/Pillow fixture references.

**Spec:** docs/superpowers/specs/2026-10-23-hdr-sdr-design.md; user explicitly selected HDR→SDR. Builder check: nothing important left; sample precision/range remain facts to verify.

- HDR metadata missing/conflicting/unsupported must not enter ordinary SDR path.
- HLG luminance OOTF, black, low signal, saturated colors, transparent highlights and image-peak normalization remain finite and bounded.
- Every bridge and resize uses normalized SDR exactly once; owned temp files and foreign outputs stay safe.
- Resize reference checks visible content and all alpha, not only dimensions, with mutations proving sensitivity.
