# ShiftWheel daily-use implementation plan

**Goal:** Implement the approved next release: reliable gesture, visible progress/history, saved conversion settings and sequential queue; preserve the remaining approved roadmap for subsequent releases.

**Architecture:** Native C++20/Win32 and Direct2D remain. A job captures its own ConversionOptions. Child workers report bounded progress events through an inherited anonymous pipe; no idle polling. A native control panel exposes session history, queue actions and persistent settings. Existing engine processes, original preservation and exclusive publication stay intact.

**Spec:** Approved seven-stage roadmap in chat, 2026-10-22. Immediate release priorities were gesture, progress, quality settings. Queue is included because it shares the new job model. Hardware codecs, HEIC/animation, installer/update deployment are separate release deliverables and must not be claimed implemented by this release.

## Shared contracts

- `options.h`: enum `QualityPreset { Compact, Balanced, High }`, enum `ResourceMode { Economy, Balanced, Fast }`; `ConversionOptions { QualityPreset quality=Balanced; ResourceMode resources=Balanced; unsigned image_max_dimension=0, video_max_height=0, audio_bitrate_kbps=0, pdf_dpi=144; }`.
- `Settings { ConversionOptions conversion; std::filesystem::path output_directory; std::map<Category,std::vector<Format>> wheels; bool auto_show_progress=true; }`.
- `load_settings(path)`, `save_settings(path, settings)`, `load_options(path)`, `save_options(path, options)`, `validate_options(options)`, `configured_formats(input,settings)`. Missing settings file returns defaults; invalid file throws. Output directory empty means source directory. Settings file `ShiftWheel.ini` beside EXE. Options passed to child as exclusive owned staging snapshot.
- `convert_file(input,output,temporary,format,const ConversionOptions& options={})`. Converter module APIs can gain options as final default argument; old tests remain valid. Balanced preserves existing defaults; explicit overrides apply only where relevant.
- `progress.h`: `struct JobProgress { int percent=-1; std::wstring stage; }; void report_progress(int,const std::wstring&);` child stdout event lines. Worker exposes `JobProgress progress() const`, `wm_worker_progress=WM_APP+21`, `start(input,format,notify,const ConversionOptions& options={}, const fs::path& output_directory={})`. No heap pointers in posted messages.
- `run_engine(executable,args,log,timeout,double duration_seconds=0)`; positive duration enables FFmpeg stdout progress parsing; stderr remains in log. Parent adds `-progress pipe:1 -stats_period 0.25` only on media conversions. Final 100 means output published, not merely encoder done.
- Panel model: `PanelRow { uint64_t id; std::wstring name,target,status,detail; bool retryable=false,removable=false,openable=false; }`; `PanelState { std::wstring headline,detail; int percent=-1; bool running=false,queue_paused=false; std::vector<PanelRow> jobs; }`.
- `PanelActions { std::function<void()> cancel,pause_queue,clear_queue; std::function<void(uint64_t)> open_result,retry,remove; std::function<void(const Settings&)> save; }`.
- `ControlPanel`: initialize(HINSTANCE,const Settings&,PanelActions), update(const PanelState&), show(bool settings=false,bool activate=true), shutdown(), handle(). Closing hides it. UI is event-driven; explicit buttons open/activate. Progress may show without stealing focus.

## Acceptance and review focus

Preserve source and existing output on failures/cancel. No helper survives cancellation. No active timers/pipes while idle. History remains available with Windows notifications disabled. Invalid settings never become arbitrary engine arguments. Closing panel does not exit app or cancel work. Closing app cancels active work and leaves pending jobs unstarted. Every queue item uses immutable settings. Animated/HDR unsupported inputs continue explicit refusal. No unconfirmed claims about mixed physical monitors or clean Windows.

Repository is unborn with read-only .git, so use current isolated workspace and no git mutation. Record verification here. Product code changes are authorized by user's approval; no repeated confirmation gate.
