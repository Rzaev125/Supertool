# План улучшений ShiftWheel после 0.6.0

> При реализации: использовать superpowers:executing-plans и проверять каждый этап отдельно. Пользователь утвердил реализацию этапов 1–2 для 0.7; затем утвердил продолжение этапов 3–4; 5–6 остаются дорожной картой.

**Цель:** сделать конвертацию через колесо предсказуемой и ненавязчивой, затем улучшить восстановление задач, обновления и охват форматов.

**Архитектура:** сохранить C++20 / Win32 / Direct2D, отдельные процессы движков и последовательную очередь. Фоновое обслуживание выполнять по событиям и редким проверкам, без постоянного опроса.

**Основание:** README, текущие options/app/job_queue/updates, документы проверки 0.6.0 и замечание пользователя о появляющемся окне конвертации. Этапы 1–2 подтверждены пользователем; статус проверок приведён в docs/acceptance-0.7.0.md.

## Уже есть

Колесо, выбор форматов и качества, очередь, история текущего сеанса, GPU H.264 с CPU fallback, HEIC/AVIF, Office/PDF/OCR, установщик, канал обновлений и опциональный автозапуск. Автоматическое открытие панели уже отключается настройкой. План не считает эти функции отсутствующими.

## Этап 6 — следующие форматы

- [ ] Сначала GIF и анимированный WebP: кадры, длительности, зацикливание, прозрачность и пределы декодирования.
- [ ] Затем HEVC и AV1 для видео с явной совместимостью контейнеров/устройств и GPU fallback.
- [ ] Затем применение EXIF-ориентации и выбор поведения метаданных; HDR — отдельным этапом с проверкой цветопередачи.
- [ ] RAW, редактируемый PDF → Word/Excel и более сложный OCR оценить отдельно, без обещания точного восстановления вёрстки.

Каждое направление принимается по настоящим файлам, проверке всего результата и сохранности источника. Наличие кодека в FFmpeg само по себе не доказывает поддержку функции.

## Порядок выполнения и выпуск

Рекомендация: сначала этапы 1–2 как небольшой выпуск 0.7; затем 3–4. Модули и новые форматы выпускать отдельно. Не начинать всё одновременно.

Для каждой задачи реализации: сначала воспроизвести требуемое поведение тестом, затем внести изменение, выполнить относящиеся к нему проверки и ревью. Перед выпуском — общий набор тестов, отдельная Windows-приёмка, точное совпадение EXE/хешей в установщике и ZIP. Публикация манифеста выполняется последней.
