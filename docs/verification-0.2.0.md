# Проверка ShiftWheel 0.2.0 — 2026-10-22

## Подтверждено

Release x64 собран MSVC 19.44 / Windows SDK 10.0.26100.0 без предупреждений.
Полный CTest: **9/9**, 0 ошибок, 58.00 секунд. Базовые тесты дополнены тремя
интеграционными наборами с настоящими движками и файлами.

- `policy`: категории, допустимые преобразования, 3/4/5 секторов, нейтральная
  зона, Shift, COPY-only, безопасные имена файлов/папок, quoting, порог жеста.
- `images`: реальные PNG/JPEG/BMP, прозрачность/белый фон/пиксели, оригинал,
  существующий выходной и временный файлы, повреждённый ввод.
- `ole_drop_contract`: настоящий IDataObject/CF_HDROP и зарегистрированный
  IDropTarget; динамические маршруты видео/таблиц, запрет смены объекта между
  DragEnter и Drop, MOVE-only, центр, Shift, batch, busy, preview, junction,
  исчезновение источника. Это COM-контракт, не жест пользователя в Explorer.
- `worker_cancellation`: рабочий процесс запускает потомка, удерживающего файл
  в вложенной временной папке. Отмена завершает дерево, очищает staging,
  сохраняет оригинал и чужой результат, не сообщает ложное «Готово».
- `application_smoke`: окно управления/трей, ожидание, корректное завершение.
- `worker_smoke`: самостоятельный EXE создаёт JPEG с белым фоном, SHA-256
  оригинала не меняется, повторная запись результата запрещена.
- `conversion_pdf`: PNG/JPG обеих страниц, 144 DPI и красный/синий пиксели,
  текст обеих страниц; отказ от защищённого/повреждённого PDF, интерактивной
  формы и скана без текстового слоя; существующая папка результата, чужой
  staging, отсутствие модуля. Пути содержат кириллицу и пробелы.
- `conversion_office`: DOCX → PDF/DOCX/ODT/RTF/TXT; XLSX → PDF/XLSX/ODS/CSV.
  Сохраняются две страницы документа, оба листа таблицы, кириллица; CSV
  содержит рассчитанные значения формул обоих листов. Поддельный DOCX
  отвергается. Файлы блокировки LibreOffice не попадают в результат.
- `conversion_media`: пять видео- и пять аудионаправлений; ffprobe подтверждает
  дорожки и длительность; видео без аудио конвертируется в видео, но извлечение
  аудио отклоняется. Проверены испорченный заголовок и испорченный H.264-пакет
  внутри валидного MOV, отсутствие частичного результата, сохранность файлов.

Колёса на 5 и 4 сектора отрисованы настоящим Direct2D-кодом и визуально
осмотрены. Первые страницы полученных DOCX→PDF и XLSX→PDF также отрендерены и
осмотрены: текст/кириллица и значения таблицы читаемы.

## Независимое ревью

Свежий read-only reviewer проверил текущий код. Критических проблем не найдено;
оба важных замечания воспроизведены падающими тестами и исправлены:

1. PDFium без form-rendering пропускал заполненные поля: PDF с интерактивной
   формой теперь отклоняется с понятным сообщением до публикации PNG/JPG/TXT.
2. FFmpeg по умолчанию терпел повреждённые кадры: добавлены `-xerror`,
   `-max_error_rate 0`, `-err_detect explode`; повреждённый пакет теперь приводит
   к ошибке, временные результаты удаляются.

Полный зелёный прогон выполнен после этих изменений.

## Ресурсы и зависимости

- EXE: **410624 байт**, статическая CRT, импорты только системных DLL Windows.
- Ожидание в трее: **0.0 мс CPU за 10007 мс**, рабочая память **13.0 MiB**.
  Это короткий замер на данной машине, не гарантированный бюджет для всех ПК.
- FFmpeg/LibreOffice — отдельные процессы по требованию; PDFium загружается
  только рабочим процессом PDF. Пониженный приоритет, одна задача одновременно,
  два codec/filter-потока FFmpeg; жёсткого лимита процента CPU нет.
- FFmpeg 9.0.2: SHA-256 архива совпал с опубликованным поставщиком.
- LibreOffice 26.8.1: SHA-256 MSI совпал; Authenticode Valid, The Document
  Foundation. Использовано только административное извлечение в проект.
- PDFium 156.0.8076.0: нативная DLL из доступного runtime pypdfium2 5.14.0,
  лицензии включены. Python используется только для тестов.

## Оставшиеся проверки и ограничения

- Полный drag → Shift → сектор → drop из настоящего Explorer/рабочего стола,
  медленный источник, несколько мониторов и разные DPI вручную не проверены.
- Не протестирована чистая Windows без установленных инструментов разработки;
  нужные VC++ DLL LibreOffice включены локально, у PDFium/приложения системные
  импорты, но отдельный clean-machine тест всё ещё полезен.
- Пограничные размеры, заполненный диск, очень длинные пути, гонка появления
  результата непосредственно в момент финального rename отдельно не моделировались.
- Ограничения: одна задача/файл, локальные пути, нет OCR/пакетной обработки,
  PDF-формы и защищённые PDF отвергаются. Дополнительные медиа-дорожки,
  субтитры и вложения не переносятся. Сложная Office-вёрстка и формулы зависят
  от совместимости LibreOffice и доступных шрифтов.

## Ручная приёмка

1. Запустить `out/ShiftWheel/ShiftWheel.exe` вместе с папкой `modules`.
2. Поочерёдно перетащить PNG, MP4, WAV, DOCX, XLSX и PDF; выбрать формат.
   Проверить результат рядом с оригиналом и сохранность исходника.
3. Проверить Shift release, Esc, центр, уход за колесо, неизвестный формат,
   папку/несколько файлов/junction. Нежелательных перемещений быть не должно.
4. У PDF→PNG/JPG проверить все страницы, у XLSX→CSV — каждый лист.
5. На длинном видео отменить задачу; убедиться, что процессы движка завершились
   и временная папка убрана. Повторить выход из приложения во время задачи.
6. Повторить жест у краёв экранов при 100%, 150% и 200% DPI.
