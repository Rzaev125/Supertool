# Проверка Supertool 0.1.0 — 2026-10-22

## Подтверждено

- Release x64: MSVC 19.44, Windows SDK 10.0.26100.0; сборка без предупреждений.
- CTest: **6/6** наборов проходят.
- `policy`: сектора, нейтральная зона, COPY-only, Shift, имя результата,
  Windows quoting с пробелами/кириллицей/обратными слешами, порог и повтор жеста.
- `images`: реальные WIC PNG/JPEG/BMP; белый фон, прозрачность PNG, цвет пикселей,
  побайтовая сохранность оригинала, отказ от перезаписи выходного/временного
  файла, отказ от повреждённого ввода без частичного результата.
- `ole_drop_contract`: настоящий IDataObject/CF_HDROP и зарегистрированный
  IDropTarget; COPY при Shift, NONE для MOVE-only/центра/отпущенного Shift/
  нескольких файлов/занятости/просмотра/исчезнувшего файла/пути через junction.
  Это проверка COM-контракта, а не полный жест пользователя в Проводнике.
- `worker_cancellation`: контролируемый дочерний процесс записывает временный
  файл и ожидает; после появления чужого выходного файла отмена не сообщает
  ложный успех, сохраняет оригинал/чужой файл и удаляет свою временную папку.
- `application_smoke`: свой экземпляр приложения создаёт окно управления,
  ожидает без работы и корректно завершается по WM_CLOSE.
- `worker_smoke`: реальный отдельный EXE создаёт JPEG, проверяется белый пиксель,
  SHA-256 оригинала и отказ от повторной записи в существующий результат.
- PNG-макет колеса создан настоящим Direct2D-кодом отрисовки и визуально осмотрен.
- PE dependencies: только системные библиотеки Windows; EXE 311808 байт на момент
  проверки (размер может измениться при пересборке).

## Независимое ревью

Критических замечаний не найдено. Оба P2 воспроизведены RED-тестами и исправлены:
1. Ложное «Готово» при отмене и чужом файле результата: успех требует exit code 0.
2. Несогласованность приёма путей и конвертера: используется общая проверка
   локального диска и всех компонентов пути; сетевой корень отклоняется до
   запросов атрибутов файлов.

Дополнительно таймер после mouse-up больше не скрывает окно с уже активным OLE
drag: завершение определяется Drop/DragLeave либо явной отменой Shift/Esc.

## Ресурсы

Первый замер: **0.0 мс CPU за 2000 мс**, рабочая память **12.8 MiB**.
Повторный замер финальной сборки: **0.0 мс CPU за 10006 мс**, **12.9 MiB**.
Это короткий замер на этой машине после запуска, а не гарантированный бюджет.
Нагрузка во время обработки зависит от файла и отдельно не ограничивается
процентом CPU. Пониженный приоритет уступает процессор другим приложениям.

## Ещё не подтверждено

- Полный drag -> Shift -> сектор -> drop из реального Проводника/рабочего стола,
  включая медленный источник и закрытие колеса до первого DragEnter.
- Несколько мониторов, разные DPI, края экрана, перезапуск Explorer,
  переключение сеанса и сочетания с приложениями повышенных привилегий.
- Отдельные фикстуры EXIF orientation, 40 млн пикселей, многокадрового ввода,
  длинных путей, заполненного диска и гонки появления результата непосредственно
  в момент финального MoveFileEx. Защиты в коде есть, эти сценарии не объявлены
  протестированными.
- Ревью отметило лишнюю перерисовку на неизменном DragOver; это небольшая
  оптимизация на следующий этап, ожидание в трее она не затрагивает.

## Ручной приёмочный сценарий

1. Запустить EXE и убедиться в наличии значка в трее.
2. Перетащить локальный PNG, зажать Shift, выбрать JPG, отпустить мышь.
   Проверить появление JPEG и сохранность PNG.
3. Повторить с отпусканием Shift, Esc, сбросом в центр и уходом за границу круга.
   Конвертация не должна запускаться, файлы не должны неожиданно перемещаться.
4. Попробовать текстовый файл, папку, два изображения и файл через junction:
   они не должны приниматься.
5. Повторить у краёв экранов при 100%, 150%, 200% DPI.
6. Запустить большое изображение, отменить через трей, проверить оригинал и
   отсутствие временной папки; затем проверить выход из приложения во время задачи.

До выполнения этого сценария прототип не считается готовым для ежедневной работы.
