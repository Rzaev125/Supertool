## Точность HDR

Замечание Minor из [ревью0.14](review-0.14.0.md) закрыто отдельным `hdr_precision`:
lossless identity-matrix RGB градиенты содержат все1024/4096 кода10/12 бит для PQ/HLG AVIF/HEIC.
Известные до кодирования значения сравниваются с16-битными отсчётами; допуск2 кода,
а не256 из широкого lossy chart. Плотный тест проверяет каждый RGB отсчёт; альфа и tone-map
продолжают проверяться в `hdr_images`. Все16 намеренных PNG16 подмен nearest/truncated8-bit
отвергаются. Старый допуск256 пропустил первую такую мутацию (RED `build/precision14-red.log`).
GREEN:4/4 PASS14.16с, `build/precision14-focused.log`,8 реальных вариантов и16 мутаций.

Фикстуры закрепляют способ расширения отсчётов каждого декодера независимо от его вывода:
avifdec нормализует q к65535, HEIC matrix0 RGB в текущем комплекте выводит q<<(16-depth).
В обоих случаях все10/12 исходных бит сохранены. Для HEIC10-bit q=1023 даёт65472,
шаг64; `heif-info` подтверждает10 бит и RGB matrix0. Это не8-битная потеря точности.
См. [PNG writer libheif1.23.6](https://github.com/strukturag/libheif/blob/v1.23.6/heifio/encoder_png.cc).
Изменение/обновление кодеков требует новой проверки этой договорённости.

## Доступная Windows-приёмка

Через computer-use открыт собственный `build/ui-acceptance-0.14/Supertool.exe --panel`:
панель «Готов к конвертации», очередь0, вкладка настроек, список разделов и настройки колеса
отображаются; автопоказ и автозапуск выключены, уведомления выключены. Настройки настоящих
копий приложения не читались и не изменялись. Скриншоты panel/settings/wheel-settings в той же папке.
Тестовая копия закрыта по проверенному собственному PID, SHA256 сгенерированного PNG сохранён.

Доступный `sky.drag` не принимает модификаторы, а `press_key` не поддерживает удержание
клавиши между действиями. Поэтому настоящий Explorer drag+Shift, последовательности Shift
до/после drag, отпускание Shift и Esc во время drag здесь **не проверены**.
Отдельный preview запуск не дал targetable окна в computer-use; скриншот реального колеса
и его Esc-поведение не заявляются проверенными. OLE/animation автоматические тесты остаются
отдельным доказательством и не заменяют физический жест. Несколько мониторов/DPI,
чистая Windows VM, заполненный диск остаются открытыми.

проверяющий не запускал процессы/тесты и не изменял файлы. Условие полного зелёного набора выполнено.

Пакеты разделены на core (встроенные изображения без модулей) и full (все закреплённые модули).
Имена локальных артефактов: `Supertool-0.14.0-core-win-x64.zip`,
`Supertool-0.14.0-win-x64.zip`, соответствующие `-setup.exe`, исходники `-source.zip`.
Пакетирование сначала проверяет точный инвентарь модулей, затем копирует только допустимые файлы.
Проверка установщика выполняется специально собранной ISOLATED-TEST копией с тем же payload,
в отдельной папке build/installer-tests, без регистрации/ярлыков настоящей установки.
Итоговые хеши и фактический результат installer lifecycle фиксируются отдельно в
`out/artifacts-0.14.0.json` и исходном отчёте `docs/artifacts-0.14.0.md` после создания артефактов;
эти последующие доказательства не входят в проверяемые ими бинарные пакеты.
Настоящих ключей/сертификата нет: пакеты будут unsigned, Authenticode и подписанный CI-выпуск
не активируются. Требования подключения описаны в [signing.md](signing.md).
Старые пакеты out сохраняются, новая публикация GitHub не выполняется.
