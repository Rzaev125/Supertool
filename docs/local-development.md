# Локальная разработка ShiftWheel

Разработка ведётся в `D:\IT\Project\Supertool`. Локальные проверки не публикуют
релизы, не изменяют публичные каналы и не устанавливают приложение.

## Проверки одной командой

По умолчанию CMake включает `SHIFTWHEEL_LOCAL_DEVELOPMENT=ON`: приложение не
обращается к каналам обновлений и не загружает модули. Сохранённые значения INI
не сбрасываются. Настройки объясняют ограничение; удаление модулей и автозапуск
сохраняют прежнюю логику. Будущий официальный workflow явно задаёт `OFF`, но
сейчас не запускается и требует отдельной подготовки источника CAB.

После сборки Release:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-local.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-local.ps1 -Suite Conversions
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-local.ps1 -Suite Full
```

Можно использовать `pwsh` вместо `powershell`. Python берётся из CMakeCache;
при необходимости задайте `-Python C:\path\to\python.exe`. Нужны тестовые пакеты
из `tests/requirements.txt`, CTest, собранные тестовые EXE и соответствующие модули.
Сценарий не загружает эти зависимости автоматически.
Установочные инструменты при локальной проверке берутся только из сохранённого
`tools/installer-downloads`; отсутствие кэша даёт явную ошибку.

- `Smoke` — короткие реальные PNG → JPG, MOV → MP4, WAV → MP3 и DOCX → PDF.
  Проверяются размеры/пиксели, потоки и полное декодирование медиа, текст PDF и
  неизменность оригиналов.
- `Conversions` — десять групп проверок, включая AVIF/HEIC, Office, презентации,
  PDF и OCR на русском, английском и азербайджанском.
- `Full` — все зарегистрированные CTest-проверки. Если запущен основной экземпляр
  ShiftWheel, `application_smoke` явно пропускается: работающий экземпляр не
  закрывается ради проверки. Пропуски отражаются в отчёте. Ручная проверка жеста
  в Проводнике остаётся отдельной приёмкой.

Результат последнего запуска: `build/local-check/report.json`, `check.log` и
`results.xml`. Успешные фикстуры удаляются. При сбое рабочая папка сохраняется под
`build/local-check/runs/<id>` для диагностики; команда возвращает ошибку. Отсутствие
нужного теста или пропуск всех тестов не считаются успехом.
В сохранённой папке находятся собственные `report.json`, `check.log` и `results.xml`:
следующая проверка их не перезаписывает. Одновременные проверки одного проекта
отклоняются блокировкой. Короткие идентификаторы папок оставляют место для
вложенного приватного профиля LibreOffice; длинные пути проекта могут требовать
переноса checkout ближе к корню диска.

## Очистка оставшихся фикстур

```powershell
# Сначала посмотреть список:
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-local.ps1 -Cleanup
# Удалить перечисленные принадлежащие runner папки:
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-local.ps1 -Cleanup -Apply
```

Очистка работает только для помеченных папок этого runner. Активные проверки
защищены блокировкой. Чужие папки, результаты конвертации, `tools/modules`,
`out/module-assets` и кэш загрузок не удаляются. Junction/symlink при удалении
отклоняются; содержимое целевой папки ссылки не затрагивается.

## Подготовка модулей без GitHub Releases

```powershell
# Собрать только локальный CAB-распаковщик (без запуска приложения):
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Target module_unpack
python scripts/ci-bootstrap.py
# Только проверить текущий комплект, без восстановления:
python scripts/ci-bootstrap.py --verify-only
# Если закреплённые CAB находятся в другой локальной папке:
python scripts/ci-bootstrap.py --assets D:\Backups\ShiftWheel-module-assets
```

Хеши и ограничения берутся из `resources/module_catalog.json`. CAB проверяются
до распаковки; FDI использует ту же ограниченную распаковку, что приложение.
Каждый извлечённый файл сверяется с закреплённой описью. Полное новое дерево
готовится отдельно и только затем заменяет `tools/modules`; при ошибке переименования
восстанавливается предыдущее дерево. Посторонние файлы и directory links не
заменяются. При невозможности самого отката старая копия сохраняется, а ошибка
показывает её путь. Исправные модули при повторной подготовке не распаковываются.

Команда не меняет `build/Release/modules`, не устанавливает приложение и не
загружает CAB. Отсутствующие архивы нужно восстановить из своего локального
`out/module-assets` или резервной копии. Сохраняйте эти CAB: их байты закреплены
в каталоге. Новая генерация CAB может отличаться даже при одинаковых движках.
Проверка `python scripts/build-modules.py --verify-only` также не скачивает архивы.

Соберите рабочий EXE командой `scripts/build.ps1`. Для впервые созданного runtime
при закрытом приложении скопируйте подготовленные `tools/modules` рядом с EXE.
Не копируйте каталог поверх работающих движков и не вкладывайте `modules` внутрь
уже существующей папки `modules`.

`python scripts/benchmark.py` теперь использует текущий EXE и временные фикстуры,
без удалённых ZIP старых версий. Сравнение возможно с явно указанным локальным
`--baseline PATH`. Измеряются восемь сценариев, время/CPU, peak commit и суммарный RSS дерева процессов; первая итерация отделена от повторных. Все результаты сравниваются, PDF также по отрисованным пикселям. При ошибке фикстуры сохраняются с явным путём, при успехе удаляются. [Методика, результаты и ограничения](performance-0.16.md).

Автоматический `build/Release/ui_load_probe.exe` измеряет настоящий класс колеса
в отдельном процессе, включая таймеры/перерисовки после анимации.
Он входит в Full как `ui_load_quiet`; реальные жесты Проводника не имитируются.

Профили проверяются группами `profiles`, `panel_contract`, `execution`, `worker_protocol` и `profile_execution`. Последняя использует настоящий Worker и конвертеры на собственных фикстурах всех категорий, включая группу, OCR и извлечение аудио из видео. Проверяются декодирование, параметры, движки, исходные хеши и размер опубликованного результата. Неудачная фикстура сохраняется с напечатанным путём, успешная удаляется. Ограниченный протокол `SWE1` передаёт подтверждённые этапы/кодировщик/размер отдельно от прогресса `SWP1`; он не содержит пользовательских путей. Нативный тест `images` отдельно проверяет измерение WIC-файла до публикации, а `panel_contract` — исправимость ошибочных переходов между форматами.
