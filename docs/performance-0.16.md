# Нагрузка и оптимизация — локальная 0.16

24 октября 2026. Пункт 4 выполнен локально. Ручные тесты пропущены по указанию владельца; этапы 5–6 не выполнялись.

## Стенд и методика

Microsoft Windows 11 Pro, build 26300; 12th Gen Intel(R) Core(TM) i7-12700K, 20 логических процессоров; Intel UHD Graphics 770 и NVIDIA GTX 1660 SUPER. Подробности драйверов: `build/performance-environment.json`.

Сравниваются два локальных EXE рядом с одним комплектом модулей. Восемь одинаковых входных файлов, один снимок настроек (Balanced, CPU-видео, OCR eng), по три прогона каждой сборки; порядок baseline/current чередуется. Подготовка фикстур и проверка результата выполняются вне измеряемого интервала; параллельные сборки/тесты не запускались.

Время и CPU показаны медианой; commit и суммарный RSS дерева процессов — максимумами. RSS опрашивается примерно каждые 5 мс и повторно учитывает общие страницы процессов; commit — Windows PeakJobMemoryUsed, отдельная величина. CPU в JSON выражен также в процентах одного ядра и может превышать 100%.

Первый запуск серии записан отдельно от повторных. Каждый Office/OCR запускается новым процессом, Office всегда получает новый приватный профиль. Кэш ОС не сбрасывался: это не замер после холодной загрузки Windows. Небольшие синтетические файлы и три повтора не дают гарантии такой же скорости на других документах.

## Воспроизведение

Нужны собранные тестовые targets и Python с пакетами из `tests/requirements.txt`. Базовый EXE сохраняется перед изменением рядом с текущим EXE; модули не копируются. Сохранён ровно один `build/Release/ShiftWheel-perf-baseline.exe` для повторного сравнения. Команды из корня проекта:

```powershell
python scripts/benchmark.py --baseline build/Release/ShiftWheel-perf-baseline.exe --iterations 3 > build/performance-comparison.log 2>&1
if ($LASTEXITCODE) { throw 'Benchmark failed; see retained fixture path in log.' }
Copy-Item -LiteralPath build/benchmark-results.json -Destination build/performance-comparison.json -Force
```

Сценарий пишет `build/benchmark-results.json`; `performance-comparison.json` и `.log` — сохранённые артефакты данного запуска. JSON содержит SHA-256 EXE, скрипта, всех входов и снимка настроек, отдельные измерения и сводку. Успешные фикстуры удаляются, при сбое сохраняются с явным путём.

Базовый EXE: `69b58aa3807289f53dd0a7717ccda1faa2963a2e97a3d2bb32b762b3daff33f8`. Итоговый EXE: `b9ff4fcd054bb65943f8bdbfac797e8b2d8c78813373223c91016e713a0c99b9`. Полный набор тестов проверял тот же итоговый EXE.

## Подтверждённый узкий участок и изменение

Свежий профиль LibreOffice создавал `cache/opencl_profile.xml` с пробами NVIDIA, Intel и native. Диагностический запуск нового профиля: 15,64 с, CPU 7,59 с, peak commit 674 МиБ; уже подготовленного диагностического профиля: 3,60 с и 267 МиБ. Схема закреплённого LibreOffice `share/registry/main.xcd` задаёт `Common/Misc/UseOpenCL=true` по умолчанию. Проба с false не создала OpenCL-профиль и снизила commit до 267 МиБ. Артефакты: `build/performance-lo-probe.json` и `build/performance-opencl-profile.xml`.

В новых приватных профилях DOCX/XLSX и PPTX задан `UseOpenCL=false`. Профили предыдущих документов не используются повторно, макросы и обновление ссылок остаются ограниченными. Пользовательский профиль LibreOffice и INI ShiftWheel не меняются. Вычисления Calc выполняются без OpenCL; сложные таблицы с большим числом формул отдельно не измерялись. Аппаратное кодирование видео сохранено.

## Простой, колесо и отмена

Основной процесс после обычного запуска: CPU 0 мс за 3.065 с, выборочный максимум RSS 18.58 МиБ. Тот же итоговый EXE с автоматически открытым `--preview`-колесом, после анимации: CPU 0 мс за 3.055 с, RSS 46.35 МиБ. После измерения оставлен обычный экземпляр, INI сохранил прежний SHA-256. Артефакт: `build/performance-app-load.json`.

Отдельный `build/Release/ui_load_probe.exe` использует настоящий класс Wheel и событийный цикл. После анимации за 2 с: 0 таймеров и перерисовок, CPU 0 мс по счётчику Windows, RSS около 45,5 МиБ. После hide таймеров/перерисовок также нет, RSS probe остаётся около 45,5 МиБ. Открытие/закрытие имеют конечную анимацию. Это не измерение реального drag Проводника или длительного роста памяти; 0 мс в короткой выборке ограничено точностью счётчика. В Full этот контракт называется `ui_load_quiet`. Артефакт: `build/performance-ui-load.json`.

Дополнительный тест отмены настоящего Office трижды воспроизвёл остаток `engine.log`: DeleteFile возвращал ERROR_SHARING_VIOLATION (32), а сразу после cleanup файл уже открывался с DELETE. Worker теперь повторяет удаление только своей staging-папки с общим пределом ожидания 100 мс. В полном наборе отмена после profile lock завершилась за 15 мс: оригинал и существующий результат сохранены, нового результата и staging нет. Это проверка конкретной гонки, не гарантия отсутствия любого внешнего удержания файлов. Временная диагностическая печать удалена.
