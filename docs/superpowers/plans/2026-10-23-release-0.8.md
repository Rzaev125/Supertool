# Supertool 0.8 Implementation Plan

> Use superpowers:executing-plans task by task with RED/GREEN tests and one final fresh-context review.

**Goal:** implement approved roadmap stages3–4: durable queue/history and controlled update UX.
**Architecture:** C++20/Win32, event-driven atomic local stores, sequential jobs; updates remain background operations.
**Spec:** docs/superpowers/plans/2026-10-23-next-improvements.md, stages3–4.

## Constraints and decisions
- Preserve originals/results, user's running Desktop copy and stable0.7 release.
- No resumed conversion until explicit user action; active jobs become Interrupted.
- Store immutable options, source size/mtime, batch counters and bounded history; validate all data before accepting.
- Persist queue only on queue changes, never progress events. Atomic exclusive-temp replacement; reject reparse paths.
- Signing keys/certificate absent (user confirmed): implement verification/signing integration and CI secrets contract; production signing is not claimed active. No test private key in product.
- No Range resume unless identity can be proven; full checked download remains the default.
- Physical VM/login/OS/DPI acceptance remains honest and open where unavailable.

## Review focus
- Crash between job start and completion: no replay without approval, counters remain valid.
- Corrupt local state or reparse targets: no arbitrary file overwrite/delete.
- Missing/changed source and result collision: preserved originals and actionable state.
- Deferred update + busy/paused queue + restart: never installs unexpectedly.
- Signing absent vs bad signature: honest inactive integration, fail closed when configured.
