# Название Supertool и совместимость

Продукт называется **Supertool**. Новые сборки запускаются через `Supertool.exe`; имя используется в колесе, трее, настройках, уведомлениях, свойствах файла, установщике, ярлыках и новых пакетах. Логотип сохранён, имена исходных ресурсов приведены к Supertool.

Новая переносимая папка использует `Supertool.ini`, `Supertool.queue`, `Supertool.diagnostics.log` и `Supertool.update-state`. Если новый файл отсутствует, приложение использует соответствующий прежний файл `ShiftWheel.*` на месте. Если существуют оба, приоритет у Supertool. Автоматического удаления, перезаписи или объединения старых файлов нет.

Новая установка использует `%LOCALAPPDATA%\Programs\Supertool`. Зарегистрированная старая установка сохраняет каталог `Programs\ShiftWheel`, AppId и прежние пользовательские интеграции. Для её старых ярлыков и помощника обновления устанавливается совместимая копия нового EXE под прежним именем. Она также показывает Supertool. Новые ярлыки называются Supertool; существующие старые ярлыки сохраняются.

Технические идентификаторы Win32/mutex, C++ namespace, CMake-параметры `SHIFTWHEEL_*`, подпись `ShiftWheel-update-v1` и ключ `shiftwheel-prod-1` остаются совместимыми. Замена имени продукта не меняет формат подписи, ключ или закреплённые хеши модулей. Локальное восстановление принимает CAB с обоими префиксами и в любом случае сверяет SHA-256 и размер.

По отдельному распоряжению владельца первоначальный выпуск заменяется новой сборкой под тем же номером **1.0.0**. Установщики, ZIP, исходный архив и EXE имеют имя Supertool; тег v1.0.0 перемещается на новую проверенную ревизию. Старые CAB повторно публикуются под обоими именами с прежними байтами и SHA-256, чтобы существующие каталоги модулей продолжили работать. Подписанные каналы меняются только после проверки новых публичных файлов. Уже установленная 1.0.0 требует ручной установки: номер версии не увеличен.
