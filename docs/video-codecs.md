# HEVC и AV1 в Supertool 0.11

**Настройки → Конвертация → Видеокодек**:

| Выбор | Контейнеры | Звук |
|---|---|---|
| По формату (по умолчанию) | MP4/MKV/MOV: H.264; WebM: VP9 | AAC / Opus |
| H.264 | MP4, MKV, MOV | AAC |
| HEVC (H.265) | MP4, MKV, MOV | AAC |
| AV1 | MP4, MKV, WebM | AAC; в WebM Opus |

Кодек и расширение файла — разные настройки. AV1 в MOV и H.264/HEVC в WebM отклоняются с подсказкой выбрать другой контейнер. Для извлечения аудио видеокодек игнорируется. HEVC в MP4/MOV получает тег `hvc1`, AV1 в MP4 — `av01`. Поддержка воспроизведения зависит от приложения и устройства; для старых устройств выбирайте H.264. Встроенные кодеки Windows для конвертации не требуются.

Авто проверяет три настоящих кадра запрошенного кодека: NVENC → QSV → AMF → CPU. Каждая GPU-проба ограничена 5 с; в простое проверок нет. При ошибке GPU во время задачи удаляется только её временный результат и выполняется одна попытка на CPU **с тем же кодеком**. Отмена не запускает повтор. Исходник и чужой результат не заменяются. Подробности общей политики — [hardware-video.md](hardware-video.md).

HEVC на CPU: `libx265`, preset fast, CRF 30/26/22 для Компактного/Сбалансированного/Высокого; пул равен лимиту потоков режима нагрузки, frame-threads=1. AV1 на CPU: `libaom-av1`, CRF 42/32/24, cpu-used 8/6/4, row-mt=1 и прежний лимит потоков. AV1 может кодироваться долго на CPU; выбирайте H.264 или компактный пресет для быстрых задач. Потребление памяти зависит от разрешения и исходника.

NVENC использует CQ VBR, QSV global_quality, AMF CQP: HEVC 30/26/22, AV1 42/32/24. Это отдельные шкалы кодировщиков, не эквивалентное визуальное качество или размер. HEVC AMF получает только qp_i/qp_p: qp_b в этом кодировщике отсутствует. Декодирование, масштабирование и звук остаются на CPU; настройка нагрузки не ограничивает мощность GPU.

Результат — 8-битное YUV 4:2:0, ориентированное на SDR. HDR, сохранение 10/12 бит и проверенная передача метаданных не входят в этот этап. Используйте SDR-источники; качество HDR→SDR не обещается. Новых движков нет: используется прежний закреплённый FFmpeg-модуль 0.9.

В INI/снимках задания: `video_codec=default|h264|hevc|av1`. Старые настройки без поля сохраняют прежнее поведение. Очередь сохраняет выбранный кодек в SWQ2; SWQ1 читается с default. Старые версии приложения SWQ2 не читают: перед возвратом на старую версию завершите задачи и экспортируйте нужную историю.

Реальная проверка на этой машине: HEVC NVENC и Intel QSV; AV1 на CPU после отказа всех GPU-проб. Успешный AV1 на современном GPU и успешный AMD AMF не подтверждены. Тесты проверяют контейнеры, три пресета, все кадры строгим декодированием, размеры, длительность, звук, теги, PSNR, CPU-only/Auto/fallback, старую очередь и сохранность исходника. Список кодировщиков сам по себе не считается проверкой.

Первичные источники: [FFmpeg codecs](https://ffmpeg.org/ffmpeg-codecs.html), [AMD AMF](https://github.com/GPUOpen-LibrariesAndSDKs/AMF/wiki/AMF-Encoder-Settings-and-Tuning-in-FFmpeg). Точные параметры дополнительно сверены с `-h encoder=...` поставляемого FFmpeg.
